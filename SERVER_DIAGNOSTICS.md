## 2. АЛГОРИТМ РЕМОНТА

### СЦЕНАРИЙ 1: Не работает Штаб (ошибка в main.ts)
1. Босс → **1-я вкладка** (Deno) → `Ctrl+C`
2. Запуск (с озвучкой — так правильно):
   ```bash
   bash start.sh
   ```
   или вручную:
   ```bash
   deno run --allow-net --allow-env --allow-read --allow-run --allow-write --watch main.ts
   ```
   ⚠️ **Без `--allow-run` и `--allow-write` серверная озвучка (edge-tts) НЕ работает** —
   падает с «Requires run access» и уходит в системный голос телефона.
   `start.sh` сам проверяет `edge-tts` и ставит его, если нет.
   Вручную (Ubuntu 24+ / Debian 12+, Python 3.12+, PEP 668):
   ```bash
   pip install --break-system-packages edge-tts
   ```
   ❌ Просто `pip install edge-tts` НЕ пройдёт: «externally-managed-environment».
3. Если красная ошибка (`SyntaxError`, `Identifier has already been declared`):
   - Босс скидывает текст ошибки
   - Архитектор находит проблему **на GitHub** и правит через `replace_in_file`
   - ❌ **НЕ заставлять Босса чинить код через консоль** — правки только на GitHub, `sync.sh` подтянет

### СЦЕНАРИЙ 2: Не работает Чат (порт 8001)
1. Босс → **4-я вкладка** (nexus_ws) → `Ctrl+C`
2. Запуск:
   ```bash
   deno run --allow-net --allow-env --allow-read main.ts
   ```
3. Если `address already in use`:
   ```bash
   pkill deno
   ```
   ⚠️ **ОСТОРОЖНО:** убьёт и Штаб, и Чат → перезапустить **оба**

### СЦЕНАРИЙ 3: Caddy не работает (502, сайт не открывается, 8443 занят)
1. Босс → вкладка Caddy → `Ctrl+C`
2. Убить зависшие процессы:
   ```bash
   pkill caddy
   ```
3. Запуск заново:
   ```bash
   cd ~ && caddy run --config Caddyfile
   ```
4. Если `tls: failed to load` (проблема с сертификатом):
   ```bash
   ls -la /root/ssl/
   ```
   - Файлов нет → перевыпуск через acme.sh с флагом `--force`:
     ```bash
     acme.sh --issue --dns dns_duckdns -d <домен> --force
     ```
   - Затем установка сертификата в `/root/ssl/`

### СЦЕНАРИЙ 4: Синхронизация с GitHub не работает
1. Босс → **3-я вкладка** (sync.sh) → `Ctrl+C`
2. Запуск:
   ```bash
   bash sync.sh
   ```
3. Если ошибка:
   ```bash
   cd ~/digital-agency && git reset --hard HEAD && git clean -fd
   ```

## 2.1. АВАРИЙНОЕ ВОССТАНОВЛЕНИЕ (VIVO → TERMUX)

> Пошаговый подъём сервера с нуля. Нужен после перезагрузки телефона —
> **автозапуска нет, после ребута всё умирает.**

### Шаг 0. Подготовка
1. Открой Termux.
2. Зайди в Ubuntu: `proot-distro login ubuntu`
3. Открой 4 вкладки (свайп слева → NEW SESSION). Переименуй их для удобства.

### Вкладка 1: SHTAB (порт 8000)
```bash
cd ~
export ZVENO_API_KEY="[ключ]"
export GITHUB_TOKEN="[токен]"
export GITHUB_OWNER="alexey17001700-coder"
export GITHUB_REPO="digital-agency"
deno run --allow-net --allow-env --allow-read --allow-write --allow-run main.ts
```

### Вкладка 2: CADDY (SSL / порт 8443)
```bash
cd ~
# Если файла caddy-linux-arm64 нет — скачать:
curl -L -o caddy-linux-arm64 "https://caddyserver.com/api/download?os=linux&arch=arm64" && chmod +x caddy-linux-arm64
./caddy-linux-arm64 run --config Caddyfile
```
⚠️ **Caddy может исчезнуть при сбое** — если бинарника нет, скачать командой выше.

### Вкладка 3: SYNC (Курьер)
```bash
cd ~
bash sync.sh
```
(Он зависнет и будет молчать. Это нормально — он следит за обновлениями.)

### Вкладка 4: CHAT (порт 8001)
```bash
cd ~/nexus_ws
export VAPID_PRIVATE="[ключ]"
export VAPID_SUBJECT="mailto:admin@example.com"
export VAPID_PUBLIC="[ключ]"
deno run --allow-net --allow-env --allow-read --allow-run main.ts
```

⚠️ **Важно про переменные Штаба:** `GITHUB_TOKEN`, `GITHUB_OWNER`, `GITHUB_REPO` нужны
для работы GitHub-инструментов Архитектора (чтение/запись файлов через `main.ts`).
Без них Штаб отвечает **401** и Архитектор не видит содержимое репозиториев.
❗ **Точные имена — `GITHUB_OWNER` и `GITHUB_REPO`.** Имена `REPO_OWNER` / `REPO_NAME`
сервер НЕ читает — с ними доступ к файлам не появится (список репозиториев работает,
а чтение/запись падает с 401/Not Found). Это был реальный двухдневный затык.
Переменные читаются **только при старте** процесса — после правки env Штаб перезапустить.

### Проверка после подъёма
```bash
curl -s  -o /dev/null -w "Shtab: %{http_code}\n" http://localhost:8000/
curl -s  -o /dev/null -w "Chat:  %{http_code}\n" http://localhost:8001/
curl -sk -o /dev/null -w "Caddy: %{http_code}\n" https://localhost:8443/
```
**Ожидаемые коды:** Штаб `405` (отвечает только на POST — норма), Чат `200`, Caddy `200`.

### ⚡ Быстрый подъём одной командой
Если не хочется руками открывать 4 вкладки — запустить скрипт вручную одной командой:
```bash
bash /root/start_all.sh
```
Скрипт поднимает всё разом (Штаб, Чат, Caddy, sync.sh) через `setsid nohup` —
процессы живут отдельно от вкладки, `Ctrl+C`/`exit` их не роняют.
Логи: `/root/shtab.log`, `/root/chat.log`, `/root/caddy.log`, `/root/sync.log`.

⚠️ **Важно:** `start_all.sh` не подставляет секреты — `ZVENO_API_KEY`, `GITHUB_TOKEN`,
`VAPID_*` должны быть заданы в окружении **до** запуска (или прописаны внутри скрипта
на сервере, но НЕ в репозитории).

| Каналы не синхронизировались | Справочник каналов через комнату `__dir__` на своём сервере (замена MQTT-топика и ntfy) |

### 🏢 digital-agency (Штаб)

| Проблема | Решение |
|---|---|
| `ws_server.ts` лежал в Штабе — нарушение архитектуры | ⚠️ Удалён из `digital-agency`, вынесен в отдельный репозиторий `nexus_ws` |
| Красный крестик (сертификат) | Починено Боссом вручную (перевыпуск сертификата) |
| **«Ошибка AI: maximum context length is 128000 tokens»** | ⚠️ В `chat.js` в модель уходила ВСЯ история чата без ограничения. **Решение:** `trimHistory()` — системный промпт всегда, дальше последние сообщения в пределах 60k символов (≈20k токенов), максимум 40 сообщений. Применяется и перед повторами в цикле (поиск/чтение файла/погода) |
| **ИИ отвечает одно и то же на все вопросы** | ⚠️ В `chat.js` в запрос уходило `image: attachedImageBase64 \|\| currentChatImage`. Фото из чата лежит в `localStorage` (`shtabChatImage_<id>`) и приклеивалось к КАЖДОМУ запросу → сервер (`main.ts`) уводил всё в `callZvenoVision` (gpt-4o-mini + промпт «опиши, что на фото»), и модель на любой вопрос описывала одно и то же фото. **Решение:** фото уходит только когда Босс прикрепил его в этом сообщении (`image: attachedImageBase64`) |
| **Озвучка: `POST /tts` → 405 Not Allowed (HTML от Caddy)** | ⚠️ В `Caddyfile` на main.ts (порт 8000) проброшен **только корень домена** (`/`) — именно туда ходит чат (`PROXY` в `chat.js`). Отдельного маршрута `/tts` нет, поэтому POST на `/tts` попадал в `file_server` → **405**. А `main.ts` обрабатывает озвучку на **любом** пути (`peek.tts` проверяется в начале `Deno.serve`). **Решение (без правки Caddy):** в `voice.js` озвучка идёт на **корень домена** `https://shtab-boss.duckdns.org:8443`, плюс запасные адреса `/tts` — функция `ttsFetch()` перебирает их и запоминает рабочий |
| **Озвучка молчит / говорит роботом телефона** | ⚠️ Штаб запускался командой **без `--allow-run` и `--allow-write`**. `main.ts` → `handleTTS` использует `Deno.Command("edge-tts")` и `Deno.makeTempFile` — без этих прав Deno бросает `PermissionDenied`, озвучка падает в `phoneSpeak`. **Решение:** создан `start.sh` (запуск с нужными флагами) + в `handleTTS` добавлен разбор причины ошибки (права / не установлен edge-tts) — теперь в «Лаборатории голосов» видно точную причину |
| **`pip install edge-tts` → `externally-managed-environment`** | ⚠️ Ubuntu 24+/Debian 12+ (Python 3.12+) по PEP 668 блокируют pip в системный Python. **Решение:** `pip install --break-system-packages edge-tts` (или `pipx install edge-tts`). `start.sh` теперь ставит сам: пробует pipx → pip3 --user → pip3, добавляет `~/.local/bin` в PATH |
| **edge-tts есть, но озвучка молчит (PATH)** | ⚠️ `Deno.Command("edge-tts")` не находил бинарник, если он в `~/.local/bin` (pip --user/pipx) — Deno-процесс не видел этот путь. **Решение:** `handleTTS` перебирает 4 варианта: `edge-tts` → `~/.local/bin/edge-tts` → `python3 -m edge_tts` → `python -m edge_tts` |
| **🔒 Замок старых репозиториев** | ⚠️ Без ключа Администратора (пин в Штабе → флаг `isBoss`) старые проекты закрыты **на запись**: `write_file`, `replace_in_file`, `delete_file` возвращают отказ. Разрешено: читать, создавать НОВЫЙ репозиторий (`create_github_repo`) и писать внутри него. Список старых — `OLD_REPOS` в `main.ts`, проверка — `isRepoLocked()` в `executeTool`. Клиент обязан передавать `isBoss` во всех запросах на запись (чат + кнопка «Внедрить» + авто-деплой). **Решение:** замок в `main.ts` + `isBoss` в `chat.js` |
| **«Бекап и откат доступны только с ключем администратора»** | ⚠️ Кнопки 🛠️ в `index.html` слали `{isBackup:true}` / `{isRollback:true}` на сервер Vivo, а там стоял старый замок `isBoss` → отказ. **Решение (build 50):** запрос на сервер убран совсем — бэкап/откат идут **напрямую в GitHub API** из браузера (`ghAPI` / `ghBackup` в `index.html`, повторяют логику `handleBackup` через git trees). Токен Босс вводит один раз, лежит в `localStorage` (`shtabGhToken`), в репозиторий не пишется. Сервер Vivo в этой операции больше не участвует |
| **«Откатить Штаб» СНОВА просит GitHub-токен (build 51 не помог)** | ⚠️ Код в репозитории чист: build 51 убрал из `index.html` `prompt()`/`ghToken`/`ghAPI`/`ghBackup`, а `main.ts` берёт токен **только** из `Deno.env.get("GITHUB_TOKEN")` (нет токена → `{"success":false,"error":"Токен GitHub не задан на сервере"}`). Причина повторного появления — **залипание оболочки**: `app.html` грузится с `?v=<timestamp>` и обновляется, а САМ `index.html` — без версии, поэтому браузер/PWA держал старую закэшированную оболочку (build 50) и её кнопка «Откатить Штаб» снова просила токен. **Решение (build 52):** в `index.html` добавлен «сторож оболочки» — сверяет свой `SHELL_BUILD` с `version.json` и при расхождении жёстко перезагружает оболочку в обход кэша (один раз, без петли). Файлы: index.html, version.json |

| **«Бэкап и откат доступны только с ключом Администратора» (вернулось после build 51)** | ⚠️ build 51 вернул бэкап/откат на сервер, но **без флага `isBoss`** — а на сервере Vivo живёт старый `main.ts` с замком `isBoss` → отказ. **Решение (build 53):** в `index.html` (`shtabBackup`) в тело запроса снова добавлен `isBoss: true` — `{isBackup:true, isBoss:true}` и `{isRollback:true, isBoss:true}`. В `main.ts` ветка бэкапа/отката замка не имеет: `body.isBoss` принудительно ставится в `true` и игнорируется, токен — только из `Deno.env.get("GITHUB_TOKEN")`. Плюс в `index.html` добавлен «сторож оболочки» (`SHELL_BUILD` vs `version.json`): если браузер держит старый закэшированный `index.html`, оболочка один раз жёстко перезагружается в обход кэша (флаг в `sessionStorage` — без петли) |
| **«Бэкап и откат доступны только с ключом Администратора» — ВОЗВРАЩАЛОСЬ после каждого отката** | ⚠️ Настоящий корень: кнопка «Откатить Штаб» копирует файлы из `backup/` в корень — а в `backup/` лежал **старый** `main.ts` (с замком `isBoss`) и **старый** `index.html` (с запросом GitHub-токена). Каждый откат сам возвращал поломку. **Решение (build 54):** (1) `index.html` → `shtabBackup` шлёт `{isBackup:true, isBoss:true}` и `{isRollback:true, isBoss:true}`; (2) `main.ts` → в ветке бэкапа/отката замка нет, `body.isBoss = true` ставится принудительно и игнорируется, токен — только из `Deno.env.get("GITHUB_TOKEN")`; (3) `main.ts` → `handleBackup` при ОТКАТЕ больше не тянет из `backup/` файлы `main.ts` и `index.html` (`ROLLBACK_KEEP`) — серверный код и оболочка не откатываются никогда; (4) убран дубль «сторожа оболочки» в `index.html`, `SHELL_BUILD` = `version.json` = 54. Файлы: index.html, main.ts, version.json |

**🔑 ГЛАВНЫЙ УРОК:** Штаб и Чат — **полностью раздельные** репозитории.
**🔑 УРОК ПО ОТКАТУ:** откат не должен возвращать `main.ts` и `index.html` — иначе старый серверный замок и старая оболочка «оживают» после каждой кнопки. Сервер чата живёт только в `nexus_ws`.
**🔑 УРОК ПО БЭКАПУ:** кнопки бэкапа/отката ВСЕГДА шлют `isBoss: true` — иначе старый серверный замок на Vivo режет запрос.

## 6. ТИПОВЫЕ ПРОБЛЕМЫ И БЫСТРЫЕ ОТВЕТЫ

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| «Не вижу изменений» в PWA | Кэш `sw.js` (cache-first) | Обновить версию в `sw.js`, очистить данные сайта |
| Сообщения не ходят между устройствами | Публичный брокер заблокирован | Свой WebSocket на 443/8443 |
| Красный крестик в браузере | Нет HTTPS / просрочен сертификат / не тот домен | Проверить `ls -la /root/ssl/`, перевыпустить через acme.sh DNS |
| 502 от Caddy | Deno-процесс упал | Перезапустить нужную вкладку Deno |
| `address already in use` | Процесс висит | `pkill deno` → перезапустить оба |
| Сайт не открывается | Caddy упал | `pkill caddy` → `cd ~ && caddy run --config Caddyfile` |
| Код не обновляется на сервере | sync.sh упал | `bash sync.sh` → при ошибке `git reset --hard HEAD && git clean -fd` |

## 9. МЕХАНИЗМ ОБНОВЛЕНИЯ ШТАБА (мигающая кнопка)

**Файл-источник правды:** `digital-agency/version.json`
```json
{ "build": 2, "app": "Штаб", "note": "Меняй build при каждой правке Штаба" }
```

**Как работает (в `app.html`):**
1. При загрузке Штаб запоминает `build` из `version.json`.
2. Раз в **30 сек** перезапрашивает `version.json?t=<timestamp>` с `cache: 'no-store'` — в обход кэша.
3. Дополнительно проверяет **сразу при возврате** в приложение (`visibilitychange`) — свернул/развернул телефон.
4. `build` изменился → кнопка **«🔄 НОВАЯ ВЕРСИЯ»** мигает голубым, в шапке мигающий бейдж **«⬆ ОБНОВЛЕНИЕ»** (кликабельный), телефон вибрирует.
5. Клик → `refreshShtab()`: чистит кэши, перезагружает Штаб с `?v=<timestamp>`.
6. **Фолбэк:** если `version.json` недоступен — следит за `ETag` файла `app.html`.

**🔑 ГЛАВНОЕ ПРАВИЛО:** правка Штаба без бампа `build` = Босс не увидит обновление.
**Порядок работы Архитектора:** правишь файл Штаба → **сразу** `build +1` в `version.json` → запись в `CHANGELOG.md`.
